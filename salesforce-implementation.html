FR · ENcase study & README
The 30-second version

An 80-person industrial equipment distributor in Lyon runs sales on Excel. Quotes get lost, payments are chased by hand, company details are re-typed, and the French e-invoicing reform is coming. Over four weeks I'm taking them to Salesforce the way a consultant would: discovery first, then build, then proof. This page updates every week until launch on 2 November 2026.

The client problem

Four things going wrong today

Quotes go missing

Quotes live in spreadsheets and inboxes. Nobody knows which ones are waiting on the customer, or which discounts were approved.

Payments chased by hand

Finance finds out a payment failed days late and calls the sales rep, who calls the customer.

Company details re-typed

Legal names, addresses and NAF codes are typed in by hand, with typos and duplicates as a result.

E-invoicing reform

The French e-invoicing reform needs clean SIREN, VAT and address data, which they don't have today.

The questions this project has to answer

Where the real work is

What if Stripe sends the same payment twice?

Webhooks get retried. Every Stripe event ID is stored in a unique external ID field and upserted, so a replayed event never creates a second payment. I'll replay one on purpose to prove it.

How do you trust a public endpoint?

The webhook endpoint is on a public Salesforce Site. Nothing is processed until the Stripe signature has been verified in Apex.

What does the API do when the SIRET is wrong?

Invalid SIRET, company not found, API down: each case is handled, tested with a mock, and logged in the UAT workbook.
